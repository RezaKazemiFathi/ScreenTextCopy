این صفحه خطاهایی را پوشش می‌دهد که واقعاً برای کاربران پیش می‌آید، علت هرکدام، و راه رفعش.

## فهرست سریع

| نشانه | به کدام بخش بروید |
|---|---|
| پیام *"target machine actively refused it (127.0.0.1:10808)"* | اتصال رد شد |
| تست اتصال سبز است اما متن بدون تغییر برمی‌گردد | متن بدون تغییر برمی‌گردد |
| تست اتصال سبز است اما فهرست مدل‌ها خالی است | فهرست مدل‌ها نمی‌آید |
| خطای 401 یا 403 هنگام ترجمه | خطای احراز هویت |
| همه مدل‌ها timeout می‌شوند | همه مدل‌ها timeout می‌شوند |
| یک میان‌بر هیچ کاری نمی‌کند | تضاد میان‌بر |
| پیام *"Windows protected your PC"* | SmartScreen |
| متن OCR به‌هم‌ریخته یا خالی است | کیفیت OCR |
| ایموجی‌ها در نتیجه نیستند | ایموجی |
| یک بسته زبانی نصب نمی‌شود | دانلود بسته زبانی |
| برنامه با بستن پنجره ناپدید شد | رفتار system tray |

## ترجمه و شبکه

### اتصال رد شد

متن کامل خطا چنین است: *"Could not reach the AI endpoint ... No connection could be made because the target machine actively refused it. (127.0.0.1:10808)"*

**علت.** پروکسی سیستم ویندوز شما به یک پورت VPN/پروکسی محلی اشاره می‌کند که در حال گوش‌دادن نیست. پورت 10808 پورت پیش‌فرض SOCKS5 در v2rayN/Xray است، پس این خطا معمولاً یعنی یک کلاینت VPN در سطح سیستم تنظیم شده اما همین حالا در حال اجرا نیست.

**راه‌حل.** به **تنظیمات → ترجمه → شبکه** بروید و یکی از این دو کار را بکنید:

1. اگر اصلاً به پروکسی نیاز ندارید، **مستقیم** را انتخاب کنید تا پروکسی سیستم نادیده گرفته شود؛ یا
2. **دستی** را انتخاب کنید و آدرسی را بنویسید که واقعاً کار می‌کند، مثلاً `socks5://127.0.0.1:10808` وقتی کلاینت شما در حال اجراست.

این حالت در هر درخواست از نو خوانده می‌شود، پس ذخیره‌کردن کافی است و نیازی به راه‌اندازی مجدد نیست.

### متن بدون تغییر برمی‌گردد

**علت.** زبان مبدأ تشخیص‌داده‌شده همان زبان مقصد انتخابی شماست، پس چیزی برای ترجمه وجود ندارد و برنامه متن را همان‌طور که بوده برمی‌گرداند.

**راه‌حل.** در **تنظیمات → رفتار** یک زبان مقصد دیگر انتخاب کنید.

### فهرست مدل‌ها نمی‌آید

**علت.** آن endpoint مسیر `/models` را ارائه نمی‌دهد، پس چیزی وجود ندارد که **به‌روزرسانی فهرست مدل‌ها** بخواند. بسیاری از سرورهای شخصی و gateway ها همین‌طورند و این موضوع هیچ تأثیری روی ترجمه ندارد.

**راه‌حل.** نام مدل را با دست در کادر قابل‌ویرایش مدل تایپ کنید.

### خطای احراز هویت

**علت.** API key وارد نشده، اشتباه است، یا برای آن endpoint معتبر نیست.

**راه‌حل.** کلید را در **تنظیمات → ترجمه** دوباره وارد کنید. توجه داشته باشید که جایگزینی خودکار مدل برای خطاهای احراز هویت عمداً انجام نمی‌شود: کلیدی که رد شده باشد توسط همه مدل‌ها رد می‌شود، پس تکرار درخواست فقط اتلاف است.

### همه مدل‌ها timeout می‌شوند

**علت.** یا endpoint در دسترس نیست (که معمولاً یک مشکل پروکسی است — بخش «اتصال رد شد» را ببینید)، یا آدرس پایه اشتباه است.

**راه‌حل.** بررسی کنید که آدرس پایه بخش نسخه را داشته باشد. باید `https://api.openai.com/v1` باشد، نه `https://api.openai.com`. سقف زمانی هر مدل ۲۰ ثانیه است، پس یک endpoint کاملاً غیرقابل‌دسترس مدتی طول می‌کشد تا از تک‌تک مدل‌ها دست بکشد.

## ثبت متن و OCR

### تضاد میان‌بر

**علت.** برنامه دیگری همان ترکیب کلید را زودتر ثبت کرده، و ویندوز آن را به هرکس که اول درخواست کرده می‌دهد.

**راه‌حل.** میان‌بر را عوض کنید: **تنظیمات → رفتار → میان‌بر سراسری** (یا **میان‌بر ترجمه روی صفحه**) → **تغییر...**، سپس ترکیب جدید را بزنید.

### کیفیت OCR

**علت.** ورودی خیلی کوچک است، کنتراست کافی ندارد، یا از موتور خواسته شده زبان‌هایی را در نظر بگیرد که روی صفحه نیستند.

**راه‌حل.**

1. قبل از ثبت، تصویر را بزرگ کنید — متن بزرگ‌تر بسیار قابل‌اعتمادتر تشخیص داده می‌شود.
2. گزینه **بهبود تصویر قبل از تشخیص** را روشن نگه دارید.
3. در **تنظیمات → تشخیص متن**، **فقط** زبان‌هایی را انتخاب کنید که در ناحیه مورد نظرتان وجود دارند. انتخاب چند زبان، هم به دقت و هم به سرعت آسیب می‌زند.
4. هرجا امکانش را داشتید، از متن کم‌کنتراست یا با هم‌آمیزی شدید پرهیز کنید.

### ایموجی

**علت.** Tesseract به‌هیچ‌وجه نمی‌تواند ایموجی را تشخیص دهد — هیچ مدلی برایش وجود ندارد.

**راه‌حل.** ندارد؛ این محدودیت خود موتور OCR است. برنامه به‌جای تولید کاراکترهای بی‌معنی، این موضوع را با یک پیام کوچک صادقانه اعلام می‌کند.

### دانلود بسته زبانی

**علت.** اتصال اینترنت وجود ندارد، یا یک پروکسی دسترسی به `github.com` را مسدود کرده است. بسته‌ها از طریق HTTPS از مخزن رسمی `tesseract-ocr/tessdata_fast` دانلود می‌شوند.

**راه‌حل.** اتصال خود را بررسی کنید، بعد **تنظیمات → ترجمه → شبکه** را ببینید — همان حالت شبکه برای دانلود هم اعمال می‌شود. حالت **مستقیم** یا **دستی** با یک آدرس پروکسی سالم را امتحان کنید.

## رفتار برنامه

### SmartScreen

**علت.** بیلد منتشرشده code-signed نیست، پس SmartScreen نمی‌تواند ناشر را شناسایی کند.

**راه‌حل.** روی **More info → Run anyway** کلیک کنید. برای اینکه مطمئن شوید فایل دقیقاً همان چیزی است که منتشر شده، checksum آن را با `SHA256SUMS.txt` همان انتشار مقایسه کنید:

```powershell
Get-FileHash .\ScreenTextCopy-Setup-2.0.0-win-x64.exe -Algorithm SHA256
```

### رفتار system tray

**علت.** این رفتار عمدی است. گزینه *با بستن پنجره در system tray فعال بمان* به‌طور پیش‌فرض روشن است، پس بستن پنجره آن را پنهان می‌کند و میان‌برها فعال می‌مانند.

**راه‌حل.** روی آیکن tray کلیک کنید تا پنجره برگردد، برای خروج واقعی از **خروج** در منوی tray استفاده کنید، یا اگر می‌خواهید دکمه بستن برنامه را ببندد، این تنظیم را در **تنظیمات → رفتار** خاموش کنید.

### شروع از صفر

اگر تنظیمات به وضعیتی رسیده که نمی‌توانید سر و تهش را جمع کنید:

1. از منوی tray برنامه را ببندید (**خروج**).
2. فایل `%AppData%\ScreenTextCopy\settings.json` را پاک کنید.
3. برنامه را دوباره اجرا کنید. همه چیز به حالت پیش‌فرض برمی‌گردد.

این کار API key ذخیره‌شده و فهرست مدل‌های کش‌شده شما را هم پاک می‌کند.

## گزارش یک مشکل

یک issue در <https://github.com/rezakazemifathi/ScreenTextCopy/issues> باز کنید و این‌ها را بنویسید:

- نسخه ویندوز شما،
- نسخه برنامه،
- کاری که در حال انجامش بودید،
- متن دقیق خطا.

> **هرگز API key خود را در یک issue کپی نکنید**، و مطمئن شوید هیچ تصویر یا لاگی که ضمیمه می‌کنید آن را در خود ندارد.
